# AI标书制作 - 产品需求文档（spec.md）

> 状态：待填充。本文档仅建立空结构，所有业务需求与功能描述等待用户逐步输入。

## 概述
- **项目名称**: AI标书制作
- **项目简介**: AI标书制作是一款用 AI 辅助生成招投标文件的工具。当前主要聚焦于监理标书的制作，核心功能包括：招标文件解析、商务标制作、技术标制作、标书检查。
- **项目目的**: 提高标书制作效率，核心目标是"不废标"。通过三条路径实现：(1) 准确解析招标文件——支持 PDF/Word/扫描件（需OCR）输入，解析结果生成解析清单，清单本身须满足"不废标"要求，需解析的内容可配置（具体配置方式待定）；(2) 快速精准制作商务标，从解析清单开始确保合规，废标风险项包括但不限于资质不响应、格式不合规、漏项等；(3) 借助大模型编写技术标（监理大纲/服务方案），目录以评分办法中的评分点为准，不能多也不能少——该部分属第二期，本期不开发。
- **目标用户**: 当前为开发者个人使用（唯一用户）；未来可能分发，本期预留扩展空间，用户管理功能留待以后。

## 目标
- **本期主线：能跑通**。本期只跑通"招标文件解析 → 商务标制作 → 标书检查"这条主线；技术标（监理大纲/服务方案）属第二期，不在本期范围内。本期不定量目标，以"能跑通 + 不废标"为准。
- **不废标**：核心底线，不可妥协。
- **解析与检查均需人工兜底**：解析完成后必须有"人工确认/修改"环节，人工确认解析清单后才进入商务标制作；标书检查完成后必须输出检查清单，供人工审核处理。解析的保障机制（如双通道解析法）后续专题讨论。

## 非目标
- **技术标（监理大纲/服务方案）制作**：属第二期，本期不做。
- **多用户/权限管理**：本期仅单用户，不做用户管理、角色权限。
- **SaaS 化部署/多租户在线服务**：本期不做，仅个人使用，分发能力预留。
- **定量性能目标**：本期以"能跑通"为准，不设解析准确率、响应时间等量化指标。
- **自动无人值守出标**：解析和检查都需人工兜底，不做全自动流程。

## 背景与上下文
- **项目动因**：个人经历触发，目的是提升个人工作效率。标书制作（尤其商务标）存在大量重复性工作，但又要求高准确率、不能废标，因此需要工具辅助。
- **参考项目**：GitHub 上的"易标"（OpenBidKit_Yibiao，https://github.com/FB208/OpenBidKit_Yibiao）。本项目基本架构与易标相近（Electron + React 桌面应用），主要区别：(1) 易标无商务标制作功能，本项目前期核心就是商务标制作；(2) 易标无多企业多项目隔离，本项目需要企业—项目两级数据隔离；(3) 易标是分发的（需注册登录、多用户），本项目目前不需要分发，仅个人使用。易标的 UI 界面和功能布局有很大参考价值，可借鉴。
- **技术形态**：桌面端应用，UI 要求漂亮。目前未确定具体技术栈、团队和时间预期。

## 功能需求

### FR-1 企业/项目管理
**目标**：实现企业—项目两级数据模型，作为整个系统的数据隔离基础。

1. **企业管理**
   - 基本信息：企业名称、法定代表人、委托代理人（必填）、联系人、联系电话、企业简介。
   - 支持创建、编辑、删除。
   - 删除限制：企业下若存在项目，则不能删除。
   - 删除去向：企业删除后进入系统回收站。

2. **项目管理**
   - 基本信息：项目名称、项目编号、委托代理人（选填）。
   - 支持创建、编辑、删除。
   - 删除方式：项目可直接删除，但需弹窗提醒确认。
   - 删除去向：项目删除后进入企业内回收站（仅当前企业可见）。

3. **委托代理人优先级**
   - 以项目信息中的委托代理人为准；若项目未填写，则以企业信息中的委托代理人为准。
   - 企业信息中委托代理人为必填（标书需要）。

4. **回收站**
   - 系统回收站：存放被删除的企业，跨企业可见（仅当前用户）。
   - 企业内回收站：存放被删除的项目，仅当前企业可见。
   - 回收站默认 30 天自动清理，保留时长可在配置中调整。

5. **全局状态与配置**
   - 全局状态：系统有"当前企业/当前项目"概念，是软件地基；进入某企业/项目后，后续操作默认作用于该企业/项目。
   - 系统级配置：在未选择/进入任何企业时，存在作用于整个系统的配置。
   - 企业级配置：进入企业后，存在作用于该企业的配置。
   - 配置优先级：相同配置项，企业级配置优先级高于系统级配置。

6. **数据隔离**
   - 企业间数据完全隔离；同一企业内项目间数据相互隔离。
   - 同一企业内素材库、模板库共享，企业间不共享。

### FR-2 招标文件解析
**模块定位**：独立模块，与商务标制作平级，是所有工作的开始和基础。

1. **入口与门禁**
   - 流程：创建企业 → 创建项目 → 招标文件解析（独立模块）。
   - 上传招标文件：支持 PDF / Word / 扫描件；OCR 自动触发（自动识别图片扫描件）。
   - 功能门禁：解析清单未确认保存前，除配置类功能外，其他业务功能模块（商务标制作、标书检查等）全部灰色不可用；清单确认保存后才解锁。

2. **解析配置**
   - 关键项（必选，不可取消，共 8 项）：项目概述、技术评分要求、项目信息、甲方信息、响应文件要求、代理机构信息、商务评分要求、无效标与废标项。相对易标的调整：交货和服务要求移至其他项；新增代理机构信息、商务评分要求、无效标与废标项。技术评分要求虽技术标属二期，本期仍解析。
   - 其他项（可选）：交货和服务要求、采购清单、投标关键节点、投标保证金、资格性审查、符合性检查、开标要求、评标要求、合同授予与签订、合同解除和终止等。
   - 配置项还含：解析方式选择、高精度解析开关。配置仅对当前项目生效；不设置时使用默认配置。

3. **解析基本原理：文本解析 + LLM 校验 + 原文锚定 + 规则库前置**
   - **规则库前置**：规则能确定的要素（如页数上限、社保月份、金额格式等）由版本化、可单元测试的规则库识别，不调用 LLM；LLM 仅承担规则覆盖不到的语义判断与全文审计。
   - 方案一（默认）：
     1. 文档解析：清洗页眉页脚 → 分章节 → 提取段落与表格，保留原文片段 + 页码坐标（主数据源，文字保真）；
     2. 规则 + 轻量分类粗分：资格条款、废标条款、商务评分、技术要求；
     3. LLM 任务（不重新提取全部条款）：识别是否为实质性要求/否决投标项、检查隐藏硬性约束（年限、数量、证书类型）、标记隐性条款（业绩须已完工、合同金额要求等），输出【是否硬性条款 + 约束条件 + 原文片段引用 + 风险标记】；
     4. 校验：LLM 输出约束必须能在原文片段找到对应文字，找不到标红（拦截幻觉）；不一致标红、人工复核；
     5. 独立全文摘要审计：LLM 通读全文输出要求大类，与解析大类做数量校验，发现大面积漏章节。
   - 方案二（高精度开关打开时，完全替代方案一）：两条完全独立链路——链路 1：解析工具 → 规则抽取 JSON；链路 2：全文文本 LLM 独立抽取 JSON；比对条目、关键字、原文片段相似度，差异标红。

4. **输出与确认**
   - 提取/比对结果全部以可编辑清单形式呈现，不一致处标红；
   - 人工确认/修改后保存清单，该清单是后续所有标书制作的基础，并解锁其他业务模块。
   - **评分表核心对象 `score_table.json`**：评分办法解析输出统一层级结构——评分大类 → 评分项 → 分值 → 所需证明材料 → 门槛条件（日期/金额/数量）。该对象一处产出、三处复用：(1) 阶段一素材提取清单来源；(2) 阶段二商务标检查清单来源；(3) 阶段四 AI 评标打分表。
   - **术语识别**：解析时判定文件类型（招标 / 采购 / 询比价，封面等位置可判），软件新生成的文字按对应术语体系（投标人/投标文件/投标函 或 供应商/响应文件/报价函 等）；询比价应答文件称"询比价响应文件"或"响应文件"，具体称谓记入动态词典。**源文件原文一律原样保留，绝不做全局术语替换**。
   - **源文件噪声容错（内部处理）**：真实文件常见目录页码错乱、编号跳号/重复、目录与正文标题不一致等编辑噪声。处理原则：章节识别以正文实质内容为准、目录仅交叉校验；比对时按内容顺序匹配而非编号数字；文字颜色、底纹等呈现差异一律视为噪声、只关注文字内容本身。噪声内部消化、不打扰用户、不进风险清单；核心是正确解析实质内容。
   - **格式文件地位平等**：所有解析出的投标（响应）文件格式均为核心文件，不存在主次之分，全部纳入与模板的逐一比对。
   - **混合章节按子节处理**：存在商务+技术混合章节（如"五、服务方案"下：供应商介绍/人员力量/业绩/荣誉为商务子节，监理大纲为技术子节）。解析时建立子节结构并标注内容性质；一期商务子节正常进素材提取、模板比对与生成，技术子节仅保留评分点标题骨架；状态机按子节记录状态。三期技术标单独制作、单独生成文件，合并方式由用户选择——**默认末尾追加，也可回填**；三期回填不改动一期商务内容。
   - **系统生成表单独外**：采购文件中注明"以交易系统生成格式为准"的文件（如开标一览表，即投标文件中的报价一览表），本质是报价事项——软件不制作、不导入、不参与模板比对；软件仅预留扩展口子（含报价录入弹窗入口）供以后扩展，本期不实现；标书检查时仅披露该文件由系统生成。状态机中标注为"系统外"。

5. **后续迭代（本期不做，记入待解决问题）**
   - 多模型配置与自动切换机制；支持读图、生图模型。待软件跑通后的功能迭代阶段再讨论。

### FR-3 商务标制作
**前提**：解析清单已确认保存；素材库、模板库已就绪。

1. **解析清单与投标文件格式**
   - 解析时同时解析出招标文件中的投标文件格式，以 docx 逐章保存到项目内（每章一个独立文件，最前面可有封面）。
   - 清单可增、删、修改，每一条都需逐一确认。
   - 若新增项（如投标文件格式中有需单独增加的内容），可给出文件路径或文件名，软件识别后纳入清单，同样需确认按钮。
   - 确认后软件自动重新识别读取，并在解析清单中给出地址链接供人工复核。

2. **素材提取清单（循环收敛）**
   - 依据清单列出待确认素材清单，人工可修改、可指定素材。
   - 软件依据清单查询素材库（带命名规范的结构化存储）：人工已指定的 → 查询有没有；未指定的 → 按招标文件清单查询最贴合的内容。
   - 按查询结果输出可编辑的查询清单，人工据此补充素材库。
   - 循环 2-3 轮后，保存素材提取清单，作为标书制作的成果文件。

3. **模板匹配与比对**
   - 模板库结构化组织：按代理机构名称 / 招标文件类型（招标/采购/询比价）。
   - 可人工指定模板（可指定到文件夹，文件夹下含一个或多个模板）。
   - 自动匹配相似度 ≥ 90% 的高相似模板；无匹配时提示，人工自选或先向模板库补充模板后重新匹配。
   - 模板为带文字和图片占位的投标文件格式；成品必须与模板保持一致。
   - 匹配成功后模板提取到项目内保存。
   - 生成文件关联表，将解析出的投标文件与模板逐一精确比对：无差异 → 直接采用；有差异 → 按 FR-5 第 6 点的差异更新规则处理（细微差异直接更新；投标函等差异较大的文件也可用解析内容直接更新，但报告中披露），排版由模板控制。
   - 在正式生成标书前，生成有差异的模板列表，列出差异项及更新内容，由人工逐一确认。
   - 本环节复用全局「统一差异清单与确认引擎」（见"工程机制"章节），差异项带置信度与原文锚点，高置信可批量确认、低置信逐条人工，冲突不自动应用。
   - 全部确认无误后 → 开始标书制作。

4. **标书制作（填充逻辑）**
   - 依据解析出的招标文件和素材提取清单进行填充。
   - 素材基本都是图片（但不全是）。
   - 文字占位：识别提取素材中的文字进行填充。
   - 图片占位：直接用提取的素材填充。
   - 填充信息分两类：A 类——从招标文件 + 企业/项目信息直接获取（如企业名称、项目编号、招标代理机构、招标人、法定代表人、委托代理人等）；B 类——从提取的素材中扫描识别获取（如人员姓名、业绩合同中的投资额等）。
   - 后期尽量通过企业/项目信息和素材库命名规范减少 B 类扫描，避免扫描错误。
   - 不自行增加内容，严格按模板格式填充。

5. **核心原则（不静默）**
   - 商务标的内容和排版格式与模板完全一致；除占位外，所有文字和内容与解析出的投标文件格式完全一致。
   - 任何不一致都必须披露，不允许静默处理。
   - 表格、图片不可跨页。
   - 模板对图片大小有限制，插入时自动缩放适配（基本不出现严重变形；制作素材库时也会考虑模板中图片大小）。

6. **最终输出**
   - 按解析出的投标文件格式，逐章生成独立 Word 文档。
   - 软件提供转 PDF 和文档合并功能。
   - **报价类文件本期不处理**：需填充真实报价的文件（如开标一览表/报价函中的报价）属报价事项，用户未提供不影响标书制作；软件仅预留报价录入入口（弹窗形式）供以后扩展，本期不实现。标书检查时若该文件缺失，按"系统生成/报价类文件"披露；制作流程不因报价阻断，全程人工兜底。

### FR-4 素材库管理
**定位**：企业级共享的素材基座，为商务标制作提供素材支撑。

1. **归属与共享**
   - 企业级共享：同一企业内所有项目共用，企业间不共享。

2. **层级分类与命名规范**（图片以 .png/.jpg 为主，其他格式按需；日期统一 YYYYMMDD，长期有效统一记为"长期"）
   - **资质**：营业执照、资质证书、体系认证证书、信用证书、企业简介、组织机构框图。命名：`营业执照.png/.jpg`；`资质证书关键字_有效期`（如`房屋建筑工程甲级_20281222`）；体系认证、信用证书同。
   - **人员**：先按人员姓名建文件夹（保留同名区分机制备用），下设注册证书、岗位证书、职称证书、身份证、毕业证书、个人荣誉证书、退休证（多页）、返聘协议（多页）、人员简历。命名：
     - `注册证书名关键字_注册有效期_使用有效期到期日`（使用有效期为证书右上角灰色标注，具体以真实图片为准）
     - `岗位证书关键字_有效期`；`职称等级关键字_专业`
     - `身份证_国徽面_有效期` / `身份证_人像面_有效期`（不使用 P0/P1，长期有效记"长期"）
     - `毕业证_专业`；`个人荣誉证书名关键字_颁发日期`
     - `人员简历_上传日期`（对应投标文件中的"拟投入监理人员简历表"）
     - 多页证件：末尾加`_P0/_P1`，页码按上传顺序
   - **业绩**：按项目名称建文件夹，文件夹命名`项目全名关键字_签订日期_总监`；下存监理合同、竣工报告、备案证书等，文件命名`监理合同_P0/P1`（竣工报告、备案证书同），页码按上传顺序。
   - **荣誉**：优秀监理企业、先进监理企业、监理示范工程、标准化工地、各奖项；命名`证书名关键字_颁发日期`。
   - **财务**：基本账户开户证明、中小企业声明函等；命名`中小企业声明函_年度`（如`中小企业声明函_2026年`）。
   - **项目独享资料库**：存放项目一次性资料（如社保等），不按层级分类、不跨项目共享。

3. **必检项（标书检查，缺失即废标）**
   - 部分注册证书左下角的手写签名 + 签名日期。开发时以用户提供的真实图片标识为准。

4. **动态关键字词典**
   - 关键字来源：归档扫描时从上传资料中识别；标书制作中发现"表述不一致但素材一致"时自动更新；用户可维护。已登记条目如"拟投入监理人员简历表"。

5. **上传与归档**
   - 共享库/项目独享库均支持：单个、批量、拖拽、扫描件上传。
   - 单页证件点"归档"直接入库；多页证件全部上传后归档，页码按上传顺序。
   - 扫描命名所需字段失败时，弹窗由用户决定命名。
   - 每个素材附带保存 OCR 文本（支持 FR-3 的 B 类信息提取，可供人工核对修改，一次纠正多项目复用）。

6. **与模板占位对应**
   - 素材命名关键字必须与模板中的占位名称对应。

7. **版本与引用快照**
   - 素材修改产生新版本而非覆盖；标书引用时记录版本快照，历史标书绑定当时版本，保证已投标文件可完整复现。

### FR-5 模板库管理
**定位**：企业级共享的模板基座（与素材库同为软件地基），定义商务标的版式与格式基准。

1. **目录结构**
   - `模板库/代理机构名/招标|采购|询比价/模板文件集`；模板文件集含章节 docx + `template.json` 元数据。
   - 层级路径由 FR-2 解析结果（代理机构 + 文件类型）直接驱动，实现快速定位。

2. **模板生成与编辑器**
   - 软件提供模板编辑器；用户提供标注 `[ ]` 的真实标书（图片位置沿用过往标书，少数全新情况用图文框指示），编辑器转换为软件可识别的模板。

3. **占位符规范（docxtpl / Jinja2 语法 —— 技术选型已确认，见 [tech-selection.md](file:///e:/bidcraft/bidcraft-master/docs/architecture/tech-selection.md)）**
   - 文字占位：`{{关键字}}`；图片占位：`{{img_关键字}}`；表格循环行：`{%tr for ...%}`/`{%tr endfor %}`；条件内容：`{%p if ...%}`/`{%p endif %}`。
   - 关键字与 FR-4 动态关键字词典、素材命名关键字三处统一；用户标注的 `[ ]` 由编辑器自动转换，无需手写。

4. **元数据与版本管理**
   - `template.json` 记录：模板名称、代理机构、文件类型、版本号、更新日期、章节文件、图片约束、备注等。
   - 模板修改保存为新版本；历史项目绑定其当时版本，新项目默认使用最新版。

5. **图片占位与尺寸约束**
   - 图片占位可设置最大宽度、最大高度（cm）；适配方式固定为等比缩放（contain），保证不变形不裁剪。
   - 尺寸约束写入 `template.json`，渲染时据此缩放，配合"表格/图片不跨页"规则，超限提示。

6. **模板与解析格式的强制比对（人工确认门禁）**
   - 用户提供的模板必须与 FR-2 解析出的投标文件格式逐一比对：除需填充的文字和图片占位外，其他内容必须与解析出的投标文件格式完全一致（比对对象为文字内容与表格结构，文字颜色、底纹等呈现差异视为噪声，忽略）。
   - 任何不一致都必须披露、列出差异，不允许静默处理。
   - 比对后的模板须经过人工确认，确认后才可用于生成商务标。
   - **差异更新规则**：一般多为细微差别，按解析内容更新模板即可。对于差异可能较大的文件（如投标函/报价函），允许直接用解析出的内容更新模板，但必须在比对报告中披露；后续使用中发现其他可按此处理的文件类型再逐步迭代。具体排版格式始终由模板控制，解析内容直接提取、不做任何修改。

7. **比对技术选型**
   - 不自研 XML 级 diff（docx XML 噪声极大，必然误报）；采用语义层比对（提取段落/表格文本 → 归一化 → 文本 diff）。
   - 先以开源方案实现（python-docx + difflib 类）；需要 Word 修订标记输出时，再评估 Spire.Doc（免费、有篇幅限制）或 GroupDocs.Comparison（商业）。
   - 本环节复用全局「统一差异清单与确认引擎」。

8. **操作与共享**
   - 支持增、删、改、查；企业级共享（同一企业内所有项目共用），企业间不共享。

## 开发路线图（Roadmap）

> 经 2026-09-27 讨论确认，按以下阶段推进；每个阶段以"能跑通、不废标"为准，逐阶段验证。

### 阶段一：解析 + 商务标主线 MVP
- **1.0（垂直骨架先行，walking skeleton）**：不先把各模块分别做全，先以"1 家企业 + 1 个项目 + 和县柳庄路真实采购文件 + 1 个云端模型"端到端打通最小链路（应用外壳 + FR-1 基础 + 模型配置与连通性测试），再横向补全功能。
  - 模型配置支持本地/云端，含**模型路由**：长文档深度解析走云端强模型；确定性填充任务不走 LLM；简单生成/敏感数据可走本地模型。
  - 每次模型调用记录模型名、token、耗时、费用，支持成本可观测。
- **1.1**：招标文件解析（FR-2，先只实现默认方案；高精度双通道后续迭代）。
- **1.2**：素材库/模板库最小可用版（含模板编辑器）+ 商务标制作（FR-3/FR-4/FR-5 主流程）。

### 阶段二：商务标检查
- 标书检查模块下设两个子功能：商务标检查、技术标检查。
- 本阶段只开发商务标检查（废标项、响应性比对、检查清单输出）。

### 阶段三：技术标制作 + 技术标检查
- 技术标基本功能（监理大纲/服务方案，目录以评分点为准）开发完成后，再做技术标检查子功能。

### 阶段四：AI 模拟评标
- 基于完整标书进行模拟评标打分，同时作为全流程最终验收（解析 → 制作 → 检查 → 模拟闭环）。

### 持续迭代项
- 双通道高精度解析、多模型自动切换、读图/生图模型、用户管理等。

## 工程机制
> 2026-09-28 经联网调研（智标宝、云境标书、中国移动智能标书平台及 2026 年学术论文）后确认的全局机制，为"不废标、不静默、人工兜底"提供工程保障。

### EM-1 黄金样本回归测试集（Golden Set）
- 从第一份样本起，将用户人工确认后的解析清单保存为期望输出（expected）；每次程序改动自动重跑全部样本、比对差异并全量披露。
- 用户后续提供的每份招标文件/投标文件样本均纳入测试集，逐步覆盖业务范围。
- 本机测试全绿后方可推送 GitHub 流水线（CI/CD）。

### EM-2 统一差异清单与确认引擎
- 适用环节：FR-2 双通道比对、FR-3 模板比对、标书检查（FR-6）、AI 评标——共四类"比对-确认"场景，统一复用。
- finding 数据模型：差异项 + 置信度（高/低）+ 原文锚点（页码/坐标）+ 处理动作（接受/拒绝/修改）。
- 交互规则：高置信建议可批量确认；低置信逐条人工；默认视图仅含高置信（V1），全量视图（V2）才显示低置信项；**冲突永不自动应用**，一律人工裁决。

### EM-3 规则库前置
- 规则能确定的检查与识别（页数上限、社保月份、金额格式、提示语残留、占位未填等）由版本化、可单元测试的规则库承担；LLM 仅做语义判断与全文审计。规则库随业务持续扩充。

### EM-4 模型路由与成本可观测
- 按任务类型路由模型（云端强模型 / 本地模型 / 不走 LLM）；每次调用记录模型名、token、耗时、费用。

### EM-5 标书生成状态机
- 标书制作的每一步（格式解析 → 人工确认 → 素材提取循环 → 模板匹配 → 差异确认 → 逐章生成 → 检查）均由状态机显式管理：每个文件、每个环节有明确状态（待处理/处理中/待确认/已确认/已生成/缺失/异常）。
- 状态转换全程留痕；任何步骤异常或文件缺失只披露、不静默，且不阻断其他可推进环节，由人工决定继续或补救。

## 非功能需求
### NFR-1 运行环境与兼容性
- **操作系统**：仅 Windows（支持 Windows 10 / 11）；macOS 等其他平台留待后续迭代。
- **分辨率适配**：需适配笔记本小屏（1366×768）至高分辨率屏（4K 缩放），界面在不同缩放下不错乱。

### NFR-2 性能
- **文档解析（本地，不含 LLM）**：约 60 页文件目标 ≤ 10 秒完成文本提取与章节切分。
- **完整解析（含 LLM 调用）**：目标 ≤ 3 分钟（受网络与云端模型影响），正式开发时按实测调整。
- **异步与进度**：所有耗时操作（解析、LLM 调用、转 PDF、合并）必须异步执行，界面实时显示进度与阶段，不得假死；允许中途取消。
- **内存**：本期不限上限，以稳定不崩溃为准。
- **业务体量基准**：招标文件约 50-60 页；投标文件含数十张图片，与和县样本相当。

### NFR-3 安全与隐私
- **API Key 存储**：云端模型 API Key 使用 Windows 凭据管理器（DPAPI）加密存储，不明文写入配置文件。
- **本地数据**：本期个人单机使用，资质/合同等本地文件不做额外磁盘加密。
- **网络**：不禁止外联（允许模型 API 之外的联网，如模型/错误相关通信）；首次发生外联行为时弹窗提示用户。

### NFR-4 易用性与 UI
- **设计风格**：参考易标界面，结合本项目需求定制，要求美观；支持明/暗双主题切换。
- **布局结构**：采用左侧导航栏 + 主工作区的桌面布局。
- **操作反馈**：所有关键操作（确认、生成、删除等）均有明确成功/失败反馈。
- **新手引导**：需要内置操作引导/帮助（功能由 AI 与用户共同迭代完成，便于长期搁置后快速回忆操作方式）。

### NFR-5 可靠性与可恢复性
- **中断恢复**：解析/LLM 调用过程中崩溃或断电，重启后基于状态机恢复——未完成步骤重新执行，已确认结果不丢失。
- **原子写入**：生成 Word、写清单等操作先写临时文件、完成后再替换正式文件，异常中断不产生半截损坏文件。
- **自动保存**：人工编辑清单（解析清单、素材清单等）时定时自动保存草稿。
- 回收站已在 FR-1 定义，无其他特殊可恢复要求。

### NFR-6 可维护性与日志
- **日志记录**：本地记录运行日志（关键操作、LLM 调用、错误堆栈），按日期滚动并限制总大小；日志中不记录 API Key 等敏感信息。
- **日志查看**：软件内置日志查看/导出入口。
- **数据完整性**：所有清单文件支持结构校验；文件损坏时明确报错，绝不静默忽略。

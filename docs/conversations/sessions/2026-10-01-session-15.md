### 节点 1：Task 22 验收发现问题
- **背景**：PR #53 合并后本地验证 Task 22 功能时，发现两处缺陷
- **决策/产出**：用户选择「两项都修，走 PR」，立即创建修复分支
- **经验沉淀**：antd Tooltip 只监听直接子元素事件，行内 span 宽度 = 文字宽度，导致行中部 hover 不触发；修复方式：span 加 `display:block; width:100%`

### 节点 2：修复 TR-22.3 锁定项 tooltip 命中区 + global.d.ts 重复声明
- **背景**：导航锁定项 disabled 状态 tooltip 无法被命中，global.d.ts 有重复的 `BidAPI.shell` 成员
- **决策/产出**：
  - `AppLayout.tsx`：span 加 `display:'block'; width:'100%'` + `data-testid="nav-locked-tooltip-trigger"`
  - `global.d.ts`：删除重复的 `BidAPI.shell` 成员声明（保留第 45-52 行的正确位置）
  - 新增 `src/__tests__/nav-tooltip.test.tsx` 3 条回归用例
  - 提交 `0089ff2`，PR #53（合并于 commit `228842e`）

### 节点 3：用户反馈「侧边车启动失败 / TypeError: fetch failed」
- **背景**：用户贴出弹窗截图，sidecar 启动失败，但错误信息只有 `TypeError: fetch failed`，无诊断价值
- **根因分析**：Node.js `child_process.spawn()` 在可执行文件路径无效时会 emit `'error'` 但不触发 `'exit'`；原 `waitForHealth()` 只靠健康检查轮询兜底，导致等待完整 `HEALTH_TIMEOUT_MS=30s` 后才报错，且错误信息无上下文
- **决策/产出**：用户选择继续修复，创建 PR #54

### 节点 4：修复 sidecar spawn 错误不立即上报
- **背景**：`electron/sidecar.ts` 中 `waitForHealth(port)` 无 spawn 失败感知
- **决策/产出**：
  - `waitForHealth` 新增 `spawnErrRef: { current: unknown | null }` 参数
  - 循环内检测 `spawnErrRef.current`，立即退出并报清晰错误
  - `child.on('error', ...)` 同步写入 ref，不再仅 log
  - 提交 `fafc66d`，PR #54（合并于 commit `2038c8f`）
- **经验沉淀**：Node.js spawn 必须同时监听 `error` 和 `exit` 事件，路径无效时只会触发 `error`，不会触发 `exit`

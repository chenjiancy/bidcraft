## 关键节点

### 节点 1：需求填充机制细化
- **背景**：用户要求建立流程保障 AI 对需求的理解无偏差，且所有产物可迭代。
- **决策/产出**：
  - 约定每次只聊一个话题，流程为「倾听 → 复述 → 追问 → 确认 → 落盘 → 推进」。
  - 确立硬约束：未收到明确开始编码指令前不得编码。
- **经验沉淀**：需求收集阶段强制"复述+确认"，是防偏差成本最低的手段。

### 节点 2：FR-1 企业/项目管理落盘
- **决策/产出**：
  - 企业—项目两级数据模型为软件地基，企业间完全隔离、项目间隔离、企业内素材/模板库共享。
  - 委托代理人规则：项目信息优先，缺省取企业信息；企业处必填。
  - 双回收站机制：系统回收站（企业）、企业内回收站（项目），默认 30 天自动清理可配置。
  - 系统级/企业级两级配置，企业级优先级更高。
- **经验沉淀**：删除限制（企业下有项目不可删）+ 回收站，兼顾安全与可恢复。

### 节点 3：FR-2 招标文件解析落盘
- **决策/产出**：
  - 招标文件解析为独立平级模块，是所有业务的开始；清单未确认前其他业务模块灰色不可用。
  - 8 项关键项必选（相对易标：移出交货服务要求，加入代理机构信息、商务评分要求、无效标与废标项）。
  - 原理：文本解析 + LLM 校验 + 原文锚定。默认方案五步法（含独立全文摘要审计）；高精度开关打开时切换为双通道独立抽取比对，完全替代默认方案。
  - OCR 自动触发；配置仅对当前项目生效。
- **经验沉淀**：LLM 输出必须回溯原文锚定（拦截幻觉），差异全部标红交人工。

### 节点 4：FR-3 商务标制作落盘
- **决策/产出**：
  - 三阶段：确定制作内容（投标文件格式章节化 docx）→ 素材提取清单（2-3 轮循环收敛）→ 模板匹配比对（相似度 ≥ 90%，差异分细微/重大，人工逐一确认）。
  - 填充两类信息：A 类直接取自招标/企业/项目信息；B 类从素材 OCR 文本扫描，后期尽量减少。
  - 核心原则：不静默披露一切不一致；表格图片不跨页；图片等比缩放。
  - 输出逐章独立 Word，支持转 PDF 与合并。
- **经验沉淀**：文件关联表先建立解析文件与模板的对应关系，是精确比对的前提。

### 节点 5：FR-4 素材库管理落盘
- **决策/产出**：
  - 四大类（资质/人员/业绩/荣誉）+ 财务目录 + 项目独享资料库；层级与命名规范完整定义。
  - 日期统一 YYYYMMDD，长期有效记"长期"；多页证件加 _P0/_P1 按上传顺序。
  - 动态关键字词典：OCR 扫描生成、自动归并、用户可维护。
  - 每个素材附带保存 OCR 文本，一次纠正多项目复用。
  - 注册证书手写签名+签名日期为必检项（缺失即废标），待真实图片标识。
- **经验沉淀**：命名即元数据，但须配合 OCR 文本与动态词典，避免写法不一致导致检索失败。

### 节点 6：FR-5 模板库管理落盘
- **决策/产出**：
  - 目录结构：模板库/代理机构名/招标|采购|询比价/模板文件集（章节 docx + template.json）。
  - 占位符采用 docxtpl/Jinja2 规范（{{关键字}}、{{img_关键字}}、{%tr%}、{%p%}），最终随技术栈确认。
  - 模板编辑器：将用户标注 [ ] 的真实标书转换为模板。
  - 版本管理：历史项目绑定当时版本，新项目用最新版。
  - 强制比对：模板除占位外必须与解析出的投标文件格式完全一致，差异全部披露，人工确认后才可生成商务标。
- **经验沉淀**：占位符语法与渲染引擎强耦合，选型前须与技术栈一并决策。

### 节点 7：新增三条项目规则
- **数据与功能完整性规则（基座级）**：素材库/模板库是地基，任何不妥与测试问题必须披露，禁止静默与杜撰。
- **方案评估规则**：用户提出方案后 AI 先评估问题与替代方案，再进入确认。
- **测试与样本管理规则**：样本由用户提供逐步覆盖；指定路径；本机全绿后才推 CI/CD；无需脱敏，文件过大才脱敏。

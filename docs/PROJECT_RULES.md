# AI标书制作 - 项目规则（PROJECT_RULES.md）

> 本文件定义项目级硬约束与工作协议，与 `.trae/skills/requirements-dialogue/SKILL.md` 配套使用。两者均可迭代。

## 1. 编码冻结规则（最高优先级）

- **未收到用户明确的开始编码指令前，AI 不得编写任何代码。**
- 明确指令示例："开始编码""开始写代码""动手写""实现 xxx"。
- 允许的非编码动作：读写文档、查询信息、设计方案、创建/更新 skill 与项目规则。

## 2. 需求对话协议

每次讨论需求，AI 必须按以下步骤执行，确保理解无偏差：

| 步骤 | 动作 | 说明 |
|---|---|---|
| 1. 倾听 | 接收用户对某话题的描述 | 一次只聊一个话题 |
| 2. 复述 | 用自己的话重述，提炼要点 | 暴露理解偏差 |
| 3. 追问 | 针对范围、非目标、异常场景提澄清问题 | 防止遗漏 |
| 4. 确认 | 给出最终理解，等待用户明确确认 | 未确认不落盘 |
| 5. 落盘 | 写入 spec.md / checklist.md / tasks.md | 结构化沉淀 |
| 6. 推进 | 进入下一话题 | 可由用户切换 |

## 3. 文档落盘分工

| 内容类型 | 写入文件 |
|---|---|
| 项目简介、目的、目标用户、目标、非目标、功能/非功能需求、约束、假设、验收标准、待解决问题 | `.trae/specs/ai-bid-making/spec.md` |
| 需求/规划/实施/验收/发布各阶段检查项 | `.trae/specs/ai-bid-making/checklist.md` |
| 实现任务（仅在需求确认并完成规划后） | `.trae/specs/ai-bid-making/tasks.md` |
| 对话记录与经验沉淀 | `docs/conversations/` |

## 4. 迭代规则

- skill、项目规则、spec.md、checklist.md、tasks.md 均可迭代。
- 迭代必须基于用户明确指令或确认后的修改，AI 不得自行扩展业务需求。
- 重大变更（协议步骤、硬约束）需向用户说明并获得确认。

## 5. 防偏差自检（每次落盘前 AI 必须自检）

- [ ] 是否已用自己的话复述用户需求？
- [ ] 是否已澄清范围边界和非目标？
- [ ] 用户是否已明确确认？
- [ ] 写入内容是否仅来自用户确认的信息（无自行编造）？
